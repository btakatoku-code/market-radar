# Market Radar

世界の市場データを毎日分析して、iPhoneのホーム画面から見られるようにする個人用アプリです。
完全無料で動きます（APIキー不要・サーバー費用なし）。

---

## 何ができるか

| タブ | 内容 |
|---|---|
| **今日** | いまの市場環境の判定、主要指数・為替・原油・VIX・暗号資産センチメント |
| **TOP5** | PayPay証券で買える銘柄から選んだ上位候補。チャート・予測％・**銘柄ごとの的中率**つき |
| **ランキング** | 先頭が**指定銘柄（常時表示）**。以降は米国株／日本株／暗号資産／貴金属／ETF の区分別スコア順 |
| **保有** | 取得単価と数量を登録すると、損益・構成比・いまの予測を一覧。円換算で集中リスクを判定 |
| **FX** | 主要5ペアを毎日表示（**的中確率の高い順 → 裏付けの強い順**）。**MACD／RSIの補助チャート**と裏付け判定つき。確信度56%以上は「シグナルあり」、未満は参考表示 |
| **的中率** | 事前検証の全結果と、実際に配信した予測の採点結果 |

**予測期間**: 株・貴金属・暗号資産・ETFは **1か月（21営業日）先**、FXは **24時間（翌営業日）先**。

### 表示している数字は「売買コストを引いたあと」です

PayPay証券の実コストは日本株が往復1.0%、米国株が往復1.44〜1.84%
（スプレッド0.5〜0.7%×2＋為替35銭×2）。1か月で回転させると、
**予測+1%でもコスト後はマイナス**になりえます。
カードの大きな数字はコスト後、コスト前の値と往復コストも併記します。

各カードには **120営業日のチャート**（終値・20日線・50日線）、
**その銘柄の過去の的中率**（実測値・標本数・基準線つき）、
そして「詳細を見る」を開くと次が並びます。

- **期間別の予測**（1週間 / 1か月 / 3か月）とそれぞれのコスト後
- **売買コストの内訳**と、コストを取り返すのに必要な保有期間
- **為替の影響**（米国株は 株価予測 × ドル円予測 = 円建て予測）
- **下方リスク**（過去1年/3年の最大下落、同じ期間を保有した最悪値、下位5%の想定）
- **損切り価格とポジションサイズ**（ATR×2の損切りで許容損失に収まる金額）
- **決算日**（米国株）と**配当利回り**

上位候補は**値動きの相関が0.75以上の銘柄を除いて**選びます。
海運3社が並ぶような「5銘柄に見えて実質1つの賭け」を避けるためです。

**常時表示する銘柄**（スコアに関係なく毎回この順で出す）:
エヌビディア・アルファベット・マイクロソフト・アマゾン・メタ。
それ以外はすべてその日のスコア順で入れ替わります。

分析対象は **PayPay証券の全取扱銘柄 622件**（米国株262・米国ETF48・日本株298・国内ETF/REIT14）に、
貴金属3・暗号資産9・FX14ペア・市場指標13を加えたものです。

## 検証結果（重要）

過去5年分でウォークフォワード検証をしています。結果は良し悪しに関わらず全部載せます。

### まず結論 — モデルは基準線を上回っているか

| 枠 | 予測期間 | モデルの的中率 | 基準線 | 差 | 件数 |
|---|---|---:|---:|---:|---:|
| 株・貴金属など | 1か月 | 55.1% | 55.2% | −0.1pt | 56,844 |
| FX | 24時間 | 52.7% | 52.5% | +0.2pt | 5,600 |

基準線は「何もせず買っていたら上がっていた割合」です。
**株は1か月で55%前後上がるため、的中率55%はモデルの実力ではありません。**
FXも全予測では基準とほぼ同じですが、確信度56%以上に絞ると57.1%まで上がります。

### 市場環境による絞り込み — FXに効き、株には効かなかった

「今と似たテクニカル形状」だけでなく「市場の状態も似ていた局面」に絞る方式を追加し、
7通りを実測比較しました。

| 絞り込み方 | FX的中率 | t値 | 株的中率 | t値 |
|---|---:|---:|---:|---:|
| 絞り込みなし | 51.8% | 1.16 | 54.6% | 0.04 |
| VIXの水準（3段階） | 52.6% | 1.97 | 52.6% | −0.27 |
| 地合い（2段階） | 52.9% | 2.09 | 54.4% | 0.07 |
| 市場の広がり（3段階） | 53.2% | 2.77 | 53.8% | −0.01 |
| リスク許容度（3段階） | 53.4% | 2.63 | 53.6% | −0.23 |
| **リスク許容度 × 広がり（9段階）** | **54.2%** | **3.11** | 52.3% | −0.32 |

効き方が資産クラスで正反対だったため、**FXだけ採用し、株では使っていません**。
1か月という長い期間では、絞り込みで標本が減る不利が上回るためと考えられます。

判定材料はすべて無料データです。VIXの水準、S&P500の50日線に対する位置、
分析対象のうち50日線を上回る銘柄の割合。先読みを防ぐため、各時点には
**前営業日の**レジームを割り当てています。

#### この設定の再検査 — 以前の説明は誤りでした

以前ここに「絞り込みなしでは的中率50%（49.7/49.6/50.5%）で、FXの優位性は
市場環境の絞り込みそのものから来ている」と書いていました。**誤りです。**
その49.7%は全14ペアでの測定で、実際に使っている条件（主要5ペア・
確信度56%以上）とは比較になっていませんでした。

正しい条件で、時点の並びを1日ずつずらした3標本で測り直した結果です。

| 絞り込み方 | 並び0 | 並び1 | 並び2 | 平均 | 振れ幅 |
|---|---:|---:|---:|---:|---:|
| **絞り込みなし** | 56.6% | 55.6% | 54.8% | **55.7%** | **1.8pt** |
| リスク許容度 × 広がり（9段階） | 53.7% | 57.8% | 58.5% | 56.7% | 4.8pt |
| 市場の広がり（3段階） | 52.4% | 58.7% | 54.5% | 55.2% | 6.2pt |

絞り込みによる改善は平均+1.0ポイントで、標本ごとに −2.9 / +2.3 / +3.6pt と
符号が変わります。絞り込みなしの振れ幅が最も小さい点も重要です。

**優位性を作っているのは確信度の絞り込みであって、市場環境ではありませんでした。**

### 株・長期枠（1か月先） — **統計的な優位性は確認できませんでした**

56,844件の予測（100時点・8年・599銘柄）で8種類の並べ替えルールを比較しました。
`トレンドのみ` が市場を +2.85% 上回り t値2.05 に届きましたが、頑健性検査で崩れました。

**ボラティリティ上限を変えたとき（トレンドのみ）**

| 上限なし | 90% | 70% | 55% | 45% | 35% |
|---:|---:|---:|---:|---:|---:|
| +2.85% | +1.68% | +1.25% | +0.50% | +0.47% | +0.09% |

**期間を半分に割ったとき**

| ルール | 前半 | 後半 |
|---|---:|---:|
| トレンドのみ | +5.48%（t 2.47） | +0.21%（t 0.13） |
| 予測リターン（絶対値） | +5.33%（t 1.74） | +1.09%（t 0.64） |

上限を締めるほど消え、後半では効果がありません。また8通り試して1つがt値2を超える
確率は偶然でも約34%あります。優位性の証拠とは見なしていません。

### FX・短期枠（24時間先） — **統計的に有意な優位性を確認**

**分析は14ペアで行い、シグナルは主要5ペアに絞って出します。**
米ドル/円・ユーロ/円・ポンド/円・豪ドル/円・ユーロ/米ドル。
国内で最も取引量が多くスプレッドが狭い組み合わせです。

| 組み合わせ | 的中率 | 1回あたり | t値 | 件数 |
|---|---:|---:|---:|---:|
| **分析14ペア / シグナル主要5ペア** | **58.6%** | +0.121% | 3.89 | 326 |
| 分析14ペア / シグナル実質上位5ペア | 58.7% | +0.110% | 2.76 | 329 |
| 分析5ペア / シグナル5ペア（主要） | 55.5% | +0.077% | 2.34 | 506 |
| 分析14ペア / シグナル14ペア | 57.1% | +0.087% | 3.85 | 967 |

ユニバース自体を5ペアに減らすと、類似局面のプールが小さくなって的中率が
**58.6% → 55.5%** に落ちます。だから分析は14ペアのまま残しています。

単体成績ではNZドル/米ドルが最良（59.5%・前半58.0%／後半61.0%と安定）ですが、
スプレッドが広く国内での取扱いも限られるため既定には入れていません。
入れ替えたい場合は `engine/config.py` の `FX_SIGNAL_PAIRS` を書き換えてください。

**5ペアは毎日すべて表示します。** ただし優位性が確認できたのは確信度56%以上のときだけなので、
それを満たすものだけ「シグナルあり」、残りは「見送り」として薄く参考表示します。
検証400日のうち条件を満たすシグナルが出たのは229日（57%）、出た日の平均は1.4回でした。
資金計画の初期値もこれに合わせて1日1回にしています。

#### 確信度の閾値 — 勝率を上げる唯一の確かな手段

確信度を上げるほど勝率が上がる関係は、検証期間を400／360／440時点とずらしても
順位が変わりませんでした。ただし勝率を上げるほど機会は減ります。

| 確信度 | 勝率 | 1日あたり | 1回あたり | 期間をずらすと | 前半 / 後半 |
|---|---:|---:|---:|---|---:|
| 53%以上 | 52.3% | 2.13回 | +0.035% | 52.3 / 51.8 / 52.8% | 51.1 / 53.5% |
| **56%以上（既定）** | **58.0%** | 0.83回 | +0.096% | 58.0 / 57.0 / 57.9% | 54.2 / 61.4% |
| 60%以上 | 62.8% | 0.23回 | +0.202% | 62.8 / 62.4 / 60.5% | 53.2 / 72.3% |

**アプリの資金設定で選べます。** 60%は勝率が最も高いものの、前半53.2%／後半72.3%と
偏りが大きく、62.8%という数字自体の確からしさは56%より低い点に注意してください。

### 米国金利による見送り判定 — **取り下げ**

いったん採用しましたが、翌日に測り直したところ再現せず、取り下げました。
実装は `engine/rates.py` に残していますが、売買の判断には使っていません。

主張していたのは「金利が大きく動いていて予測がその向きに逆らうときは当たらない
（45.7%）」。期間ずらし検査（400/360/440時点）も、条件作りに使っていない
8ペアでの試し打ちも通っていました。

**原因は検証時点の選び方でした。** `pick_dates` は最新日から3営業日おきに
遡るため、新しい足が1本増えると400時点すべてが1日ずれ、まったく別の標本に
なります。400/360/440 の検査は時点の並びを共有しているので、この揺れを
打ち消せません。試し打ちの8ペアも、同じ時点で測っていました。

互いに1日も重ならない3標本で測ると、次のようになります。

| 条件 | 並び0 | 並び1 | 並び2 | 平均 | 振れ幅 |
|---|---:|---:|---:|---:|---:|
| 見送った分の勝率 | 54.0% | **45.7%** | 54.7% | 51.5% | 9.0pt |
| 見送り後の全体 | 53.6% | 59.8% | 59.2% | 57.5% | 6.2pt |
| 見送らない場合 | 53.7% | 57.8% | 58.5% | 56.7% | 4.8pt |

負ける取引を外していたのではなく、**負けが集まった標本を1つ見ていただけ**でした。
改善幅も −0.1 / +2.0 / +0.7pt で、悪化する標本があります。

### 検証のやり方の修正（この不具合から得たもの）

`backtest.pick_dates` に `offset` を追加し、時点の並びを1日ずつずらした
3標本で測るようにしました。step=3 なので offset=0/1/2 は互いに1日も
重ならない別々の標本になります。**期間の長さを変える検査だけでは不十分**です。

この検査で、これまで公表していた数値も直しました。

| 条件 | 並び0 | 並び1 | 並び2 | 平均 | 振れ幅 | 以前の表示 |
|---|---:|---:|---:|---:|---:|---:|
| 確信度53%以上 | 54.0% | 52.3% | 55.3% | **53.9%** | 3.0pt | 52.3% |
| 確信度56%以上 | 53.7% | 57.8% | 58.5% | **56.7%** | 4.8pt | 58.0% |
| 確信度60%以上 | 51.4% | 62.8% | 53.3% | **55.8%** | 11.4pt | 62.8% |
| テクニカル4/4のみ | 48.6% | 56.6% | 56.6% | **54.0%** | 8.0pt | — |
| テクニカル3/4以上 | 52.4% | 58.5% | 57.0% | **55.9%** | 6.2pt | — |
| テクニカル2/4以下 | 55.2% | 57.1% | 60.0% | **57.4%** | 4.8pt | — |

- 確信度60%以上の 62.8% は撤回しました。振れ幅11.4ポイント・80件では使えません。
- **テクニカルの裏付けが強いほど当たる、という関係はありませんでした。** むしろ逆で、
  4/4揃っているものが最も低い。「MACDとトレンドが揃うと59.1%」という以前の記述も
  撤回し、裏付けの強弱表示そのものをやめました。

### 試して不採用にした情報源

テクニカル以外の情報を足せば的中率が上がるのではないかと考え、無料で取れるものを実測しました。

#### CFTC建玉報告（投機筋の売買持ち高）— **不採用**

米商品先物取引委員会が毎週公表する公式データ。鍵不要。実装は `engine/cot.py`、
検証は `tests/run_cot.py` と `tests/run_cot2.py`。先読みを防ぐため、
火曜時点の建玉は翌日曜以降でないと参照しないようにしています。

主要5ペアで8通りの条件を試すと、逆張り系の2つが3期間そろって改善しました。

| 条件 | 主要5ペア | 残り10ペア（条件作りに未使用） |
|---|---|---|
| 条件なし | 58.0 / 57.0 / 57.9% | 54.3 / 54.7 / 52.6% |
| 偏り大きい時の逆張り | 59.6 / 59.8 / 62.2% | **49.0 / 50.4 / 51.3%** |
| 週間の増減と逆向き | 60.5 / 59.7 / 59.7% | **53.3 / 53.0 / 53.0%** |
| 両方とも逆向き | 59.8 / 59.1 / 60.4% | **50.5 / 51.1 / 51.3%** |

条件作りに使っていない10ペアでは、3つとも「条件なし」を**下回りました**。
改善ではなく悪化です。8通り×5ペアから良く見えたものを拾っただけでした。

**期間をずらす検査だけでは、この形のまぐれは防げません。** 複数の条件を試したときは、
条件作りに使っていない対象で試し直す必要があります。

#### SEC EDGAR（米国企業の決算数値）— **見送り**

連絡先を名乗る正規のUser-Agent（SECが案内している形式）では5通り試して全部403でした。
ブラウザに偽装したときだけ通る状態だったため、取得しない判断をしました。

#### 取り下げた主張：曜日と経済指標

いったんは「月水かつ自通貨の指標がある日は的中率64.2%」として採用しましたが、
**検証期間をずらすと効果が消えたため取り下げました。**

| 区分 | 400時点 | 360時点 | 440時点 |
|---|---:|---:|---:|
| 基準（全体） | 55.6% | 55.5% | 54.4% |
| 月水＋自通貨の指標 | 56.2% | 57.8% | 54.6% |

前半64.7%／後半63.6%と分割検査は通っていたため採用しましたが、それだけでは
不十分でした。**以後は期間をずらしても順位が変わらないかを必ず確認します。**
経済指標カレンダーは「明日この通貨の指標がある」という情報表示としてだけ残しています。

#### 表示順とペアの選び方

5ペアは **的中確率の高い順 → 裏付けの強い順** に並べます。的中確率は、その確信度が
属する区分の実測勝率（53%区分=52.3% / 56%区分=58.0% / 60%区分=62.8%）を使います。

**「14ペアから的中確率上位5つを毎日選び直す」方式は採用していません。**
実測したところ勝率が下がったためです。

| 選び方 | 勝率400 | 勝率360 | 勝率440 | 1日 |
|---|---:|---:|---:|---:|
| **固定5ペア（採用）** | **58.0%** | **57.0%** | **57.9%** | 0.83回 |
| 確信度上位5（14ペアから） | 56.4% | 56.1% | 55.2% | 2.29回 |
| 裏付け→確信度 上位5 | 56.3% | 56.7% | 54.6% | 1.17回 |

3つの検証期間すべてで固定5ペアが上回りました。主要5ペア自体の成績が良く、
入れ替えると質の劣るペアが混ざるためです。

#### 補助分析（MACD・RSI）#### 補助分析（MACD・RSI）

FXカードには価格チャートと時間軸を揃えた **MACD（12,26,9）** と **RSI（14）** の
サブチャートが並びます。さらに予測方向とテクニカルの向きが一致しているかを
「裏付け」として4項目で判定します。

| 条件 | 件数 | 的中率 | 1回あたり | t値 |
|---|---:|---:|---:|---:|
| 条件なし | 967 | 57.1% | +0.087% | 3.85 |
| **MACDとトレンドが両方一致** | 340 | **59.1%** | +0.113% | 3.39 |
| ボリンジャーの端（逆張り） | 246 | 58.9% | +0.119% | 2.96 |
| ADX25以上（方向感あり） | 376 | 58.8% | +0.118% | 2.51 |
| RSIが50をまたぐ向きと一致 | 517 | 56.9% | +0.094% | 2.99 |

裏付けがあると的中率は2ポイント上がりますが、**機会が3分の1に減ります**。
強制的に絞ると総利益はむしろ下がるため、除外はせず「裏付け 強い／普通／弱い」
として表示するだけにしています。なお8通り試した中の最良なので、
2ポイントの改善は誤差の範囲かもしれません。

### 「1日1万円」について

資金4万円で1日1万円は日利25%です。検証で確認できた優位性では届きません。
アプリは代わりに次を表示します。

- 今の資金・リスク設定で見込める1日あたりの利益
- 目標を達成するために必要な資金
- 優位性が消えた場合の損失、10連敗の確率、1日の損益のばらつき

資金・目標・リスク・取引回数は **FXタブで変更できます**（端末に保存されます）。

## TradingView について

TradingView の埋め込みウィジェットは公式に無料で使えるため、
**詳細チャート**として組み込んでいます（開いたときだけ読み込む方式）。
ローソク足・描画ツール・多数の指標・時間軸切替が使えます。

ただし **ウィジェットは表示専用で、プログラムから数値を読み取れません**。
したがって**的中率には一切関与しません**。内部API（`scanner.tradingview.com`）は
技術的には応答しますが、利用規約が自動アクセスを禁止しているため使っていません。

アプリの予測・スコア・的中率はすべて自前のデータ（Yahoo Finance / Binance /
Nasdaq / alternative.me）で計算しています。

日本株は取引所データの制限で埋め込めないため、TradingViewのサイトを開くリンクにしています。

---

## セットアップ（30分ほど）

### 1. GitHubアカウントを作る

<https://github.com/signup> で無料アカウントを作成します。

### 2. リポジトリを作る

<https://github.com/new> で作成します。

- Repository name: `market-radar`
- **Public** を選択（Privateだと GitHub Pages が有料プラン限定になります）
- 「Add a README file」は **チェックしない**

> 表示されるのは市場データの分析結果だけで、個人情報や口座情報は一切含まれません。

### 3. このフォルダをアップロードする

パソコンで、このフォルダ（`market-radar`）の中でコマンドを実行します。
`あなたのユーザー名` の部分は自分のGitHubアカウント名に置き換えてください。

```bash
git init -b main && git add -A && git commit -m "初回作成" && git remote add origin https://github.com/あなたのユーザー名/market-radar.git && git push -u origin main
```

### 4. GitHub Pages を有効にする

リポジトリの **Settings → Pages** を開き、**Source** を **GitHub Actions** に変更します。

### 5. 初回実行

**Actions** タブ →「市場データの更新と配信」→ **Run workflow** を押します。
3〜5分ほどで完了し、`https://あなたのユーザー名.github.io/market-radar/` で見られるようになります。

以後は **2時間ごと**（日本時間の偶数時）に自動更新されます。

### 6. iPhoneのホーム画面に追加する

1. Safari で上記URLを開く
2. 下部の共有ボタン（□に↑）をタップ
3. 「ホーム画面に追加」

アプリと同じように全画面で開き、オフラインでも最後に取得したデータを見られます。

## 注意点

- **手元で見るには `python -m http.server 8765 --directory public` を起動しておく必要があります。**
  サーバーを止めると画面は開けません。GitHub Pages に配信したあとは、
  パソコンを起動していなくても iPhone から見られます。

- **GitHubの仕様で、60日間リポジトリに動きがないと定期実行が停止します。** 停止したら Actions タブから再開できます。
- 定期実行は数分〜十数分遅れることがあります。2時間ごとに実行され、1日12回です。
- 銘柄別の的中率は1週間ごとに再計算されます。その回だけ実行が数分長くなります。
- 決算日は**米国株のみ**把握しています（Nasdaqのカレンダー）。日本株の決算日と
  PER・PBRなどの指標は、無料で安定して取れる先が見つかりませんでした。
- 業種データも無料では取れないため、分散判定は値動きの相関で代用しています。
- 保有ポジションの入力内容は**この端末のブラウザにだけ**保存され、送信されません。
- 無料枠（Public リポジトリは Actions 無制限、Pages 月100GB転送）で十分収まります。

| `FX_DAILY_TARGET_JPY` | 1日の目標利益 | 10,000 |
| `FX_RISK_PER_TRADE` | 1回あたりの許容損失（資金比） | 0.02 |

## 中身の説明

```
engine/          分析エンジン（Python標準ライブラリのみ・外部依存なし）
  config.py      設定
  universe.py    PayPay証券の取扱銘柄（*.tsv から読む）
  sources.py     データ取得（Yahoo Finance / Binance / alternative.me）
  clean.py       株式分割の遡及調整・異常値の修復
  indicators.py  テクニカル指標（RSI/MACD/BB/ATR/ADX/OBV ほか）
  market.py      市場環境（レジーム）の判定
  analog.py      類似局面法による期待リターンの推定
  scoring.py     合成スコア
  fx.py          FXのシグナルと資金計画
  costs.py       PayPay証券の売買コスト
  risk.py        下方リスクと分散（相関による重複除去）
  events.py      決算日・経済指標カレンダー（Nasdaq）と配当利回り
  accuracy.py    銘柄ごとの的中率（週次で再計算）
  track.py       配信した予測の記録と採点
  backtest.py    ウォークフォワード検証
  compare.py     選定ルールの比較
  run.py         本番の実行入口
public/          PWA（アプリ本体）
  data/latest.json     毎回の分析結果（約250KB）
  data/directory.json  全銘柄の索引。保有タブを開いたときだけ読み込む（約73KB）
data/history/    配信した予測の記録（自動で追記される）
tests/           検証スクリプト
tools/           アイコン生成
```

### 予測のしくみ

「今と似た状態が過去に起きたとき、その後どうなったか」を実データから集計します。

RSI・ボリンジャー%B・20日騰落・移動平均からの乖離・ADX を3段階に区切って
約138万件の過去局面を分類します。FXではさらに **市場環境を9区分** に分けます
（株では効かなかったため使いません）。
該当するバケットの前方リターン分布から期待値を出し、上位候補にはその銘柄自身の
履歴から最近傍60件を抽出した推定を加えて、標準誤差の逆数で加重合成します。
標本が少なく誤差が大きい場合は自動的に0へ縮小されます。

前方リターンはその時点のボラティリティで正規化してから集計するため、
値動きの大きさが違う銘柄同士を同じ土俵で比較できます。

### 手元で動かす

```bash
python engine/run.py
```

検証をやり直す場合:

```bash
python tests/run_ablation.py fx 400 3
```

```bash
python tests/run_compare.py 21 100 21 0
```

有望に見えたルールの頑健性を確かめる:

```bash
python tests/run_robust.py 21 100 21
```

FXの通貨ペアの選び方と補助指標の効果を測る:

```bash
python tests/run_fx_design.py 400 3
```

```bash
python tests/run_fx.py 1 400 3
```

指標の妥当性チェック（Wilder原典の数値と照合）:

```bash
python tests/test_indicators.py
```

銘柄別の的中率を作り直す:

```bash
python engine/accuracy.py
```
